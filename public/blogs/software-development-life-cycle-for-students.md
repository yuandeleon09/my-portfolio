# Understanding the Software Development Life Cycle

Building software is more than writing code. A good system also requires planning, requirements analysis, testing, documentation, deployment, and maintenance.

The **Software Development Life Cycle (SDLC)** provides a structured way to organize these activities.

## Common SDLC activities

A project may include:

1. Planning
2. Requirements analysis
3. System design
4. Development
5. Testing
6. Deployment
7. Maintenance

Different development models organize these activities differently.

## Why requirements matter

One of the biggest lessons I have learned from academic projects is that coding a feature is easier when the requirements are clear.

Before development, it helps to identify:

- who will use the system
- what problems the system solves
- what data is needed
- what the system should and should not do
- what constraints exist

Without clear requirements, developers can spend time building features that are not actually needed.

## Testing is part of development

Testing should not be treated as something done only at the end.

Developers can test individual functions, modules, integrations, user workflows, and the complete system.

For example, a reservation system should test more than whether a button works. It should also verify that unavailable resources cannot be reserved and that the correct records are stored.

## What I learned

The SDLC helped me understand why system development should be approached as a process instead of simply opening an editor and starting to code.

Good planning reduces confusion later and makes it easier to explain how a system was developed.
